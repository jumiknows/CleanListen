# Benchmarking

The original CleanListen notebook reports promising prototype results. The productized repository separates those historical results from metrics generated by the current CLI.

## Run a benchmark

```bash
cleanlisten benchmark data/labeled_lines.csv \
  --json reports/benchmark.json
```

CleanListen auto-detects common text and label column names. Override them when needed:

```bash
cleanlisten benchmark data/labeled_lines.csv \
  --text-col line \
  --label-col decision \
  --group-col document_id \
  --json reports/benchmark.json
```

## Prefer document-grouped splits

A random line split can place lines from the same paper in both training and test sets. That makes the test easier than deployment on a completely unseen document.

When a document identifier is available, CleanListen uses `GroupShuffleSplit` so complete documents remain together. The CLI reports the split type explicitly:

- `document-grouped` — preferred
- `line-stratified` — useful for the prototype dataset, but weaker evidence

## Metrics

- **Accuracy** — fraction of all lines classified correctly
- **KEEP precision** — when CleanListen keeps a line, how often it is actual content
- **KEEP recall** — how much of the content CleanListen preserves
- **KEEP F1** — balance of content precision and recall
- **SKIP specificity** — how often layout/noise lines are correctly removed

For accessibility, KEEP recall matters especially: deleting real methods, results, or discussion text is generally more harmful than leaving a small amount of noise behind.
